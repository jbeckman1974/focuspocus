# Application architecture

This design takes the synthetic outline in M1 through the first private, persistent release in M2. It also defines the boundaries that recurrence, shared workspaces and offline editing will need. The [feature register](FEATURE_PARITY.md) owns reference behavior and open observations. The [verification plan](VERIFICATION_PLAN.md) owns fixtures and expected evidence. All contracts below are planned.

## Components and ownership

| Component | Responsibility | Boundary |
| --- | --- | --- |
| React and TypeScript browser application | Full-window perspective rail, project/tag sidebar, editable outline, resizable panes and collapsible inspector | One command dispatcher owns selection, editing and unsaved drafts. M1 supplies a fixture transport. From M2, the same controls call the same-origin API. Vite builds the static assets. [React component model, S13](https://react.dev/learn) |
| Django and Django REST Framework web process | Authenticates, resolves membership and calls domain commands or authorized queries. Serves the UI and versioned API from one origin | Run behind the HTTPS proxy with a production application server. Only the web process accepts browser traffic. |
| Domain modules in one application | Accounts and membership own access. Outline owns structure and ordering. Scheduling owns effective state, availability, repetition and review. Perspectives own queries. Content owns notes/files. Transfer owns import/export. Integrations own reminders, calendar and capture adapters. | Commands coordinate modules inside one database transaction. Views, imports and jobs call the same rules. The browser cannot set a computed field. |
| PostgreSQL | Authoritative objects, relationships, identities, sessions, personal settings, binary content, versions, change records and durable jobs | Only web, worker and controlled maintenance commands have database access. Full-text search starts in PostgreSQL. Add a separate search service only if measured queries need one. |
| Background worker | Claims SQL jobs, rechecks authority, performs slow work and records outcomes | Uses the web application's image digest and domain modules. External calls happen outside task-edit transactions. |

Web, worker and the migration command use the same application image. Each release index selects the native ARM64 variant on the MacBook's Linux VM and the native AMD64 variant on the production host. Both variants share the same API, schema and migration history. Dependency builds, native CI checks and image identities are specified in [operations](OPERATIONS.md). One database keeps task edits, repeat generation, change notification and job creation under a single commit. A lock per workspace trades write throughput within one workspace for straightforward recovery and reliable ordering. Measure queueing on the large-workspace fixture before splitting that boundary.

## Logical records and ownership

The following are logical records. Several may share a physical table. Use stable UUIDs for content, monotonic versions for mutable records and a database-enforced workspace reference on every content relationship. Actor-specific state has an additional user key.

| Records | Relationships and invariants |
| --- | --- |
| Account, session, device, recovery, external identity | Each interactive account gets one private workspace, atomically with its owner membership. An OIDC identity binds a verified issuer and subject to an account. Devices and sessions can be revoked independently. |
| Workspace, membership, invitation | Membership is unique by workspace and user. A private workspace has one member. In M5 a shared workspace has at least one owner and explicit membership. Invite redemption and revocation check the current role in a transaction. |
| Outline item, parent list, Inbox placement | An item has one workspace, kind, direct properties, version, creation/modification times and one structural parent. Each ordered child list has its own revision, including the Inbox and project root. Track unresolved Inbox filing and intended project independently so arranging a capture never creates a second task. |
| Tag, item–tag, optional place | Tags form a separate acyclic workspace tree with state, sibling order and an optional mutually exclusive group. Item–tag is a unique workspace-scoped pair. Store a named place/radius on an eligible tag. A device's current position is transient by default. |
| Schedule, series, occurrence, resolution history, project review | Schedule holds direct date values, zone intent and duration. A series has a stable ID and versioned rule. An occurrence tracks its series, predecessor, nominal position, item tree and disposition. Review state holds project, interval, last/next dates, actor and version. |
| Saved perspective, personal settings, device settings | A saved perspective belongs to a user and workspace. Store its schema version, filter expression, focus/scope, grouping, sort, layout, favorite state and original icon. User defaults and per-device layout overrides have distinct keys. |
| Note, attachment header, attachment body and link | A note has an allowlisted structured format and version. An attachment has workspace, content type, length, checksum, state and binary body in a separate PostgreSQL `bytea` record. Validate that linked items and files share a workspace. Ordinary queries select headers only. |
| Trash, archive, source mapping, transfer batch | A reversible deletion retains the affected subtree and its former placement. An archive preserves historical records. A batch stores its source fingerprint, parser version, mappings, warnings, affected IDs and versions so retries and rollback are attributable. |
| Change, operation receipt, audit, job, delivery | Scope these to a workspace or a single user. Store an authorized operation's actor, key, request fingerprint and result references. Change records carry affected IDs, list/subtree invalidations or deletion markers. Jobs store owner, deduplication key, lease, attempts, next attempt and outcome. |

Enforce same-workspace links with composite foreign keys such as `(workspace_id, parent_id)` to `(workspace_id, item_id)`. Apply the same principle to tags, attachment links, series, import mappings and personal references. Check type and cycles under the same workspace lock as the write. Check the current role on all list, count, search, file, export, job, event and command paths. Runtime and migration database roles are separate. Optional row security adds a second boundary only after isolation passes with the exact deployed roles. Superusers and roles with bypass privileges evade row policies, and table owners ordinarily bypass them. [PostgreSQL row security](https://www.postgresql.org/docs/current/ddl-rowsecurity.html) · [DRF permission boundaries](https://www.django-rest-framework.org/api-guide/permissions/)

### Hierarchy and order

| Parent | Allowed children |
| --- | --- |
| Workspace project root or folder | Folders and projects |
| Inbox root | Actions and action groups awaiting filing |
| Project or action group | Actions and further action groups, at arbitrary nesting depth |
| Action | No children until it becomes a group |

Indenting the first child under an action promotes it in place to a group within the move transaction. Keep its ID, notes, direct properties and history. Give each sibling a manual position with integer gaps. Insert relative to an anchor by ID, re-spacing just that list when needed. Check source and destination list revisions, affected item versions and anchor membership. Reject moves into self, a descendant, an incompatible parent or another workspace. A perspective sort can change display order without modifying manual positions. Reorder through a manual-order context or an explicit destination picker.

For capture, keep the item's Inbox order until its filing rule applies. Distinguish Inbox eligibility (project, tag, both or either) from the preference controlling when a resolved row disappears from an outline. A tag-only filing rule can send an unassigned item to a designated single-actions project. Keep that project's identity separate from its display name. Duplicate allocates new item IDs and rewrites internal subtree links. Restore from trash reuses original IDs and reports a conflict if original placement is unavailable. Retrieval from a native-style archive copies the selected material into the active workspace and retains its archival copy. Exact metadata carried through duplication and archive retrieval is an M0 observation. [Inbox and projects](https://support.omnigroup.com/documentation/omnifocus/universal/4.10.1/en/perspectives/) · [Database and archive](https://support.omnigroup.com/documentation/omnifocus/universal/4.10.1/en/database/)

## Authoritative task rules

The evaluator takes the ordered tree, direct values, tag state, an explicit clock, timezone context and documented policy version. It returns effective state, source item/reason, eligible view memberships and the next time at which the result could change. Queries, reminders, review, previews of imports and successor generation use this interface. Recompute on changes to ancestors, tags, order or time. A cached projection carries its dependency revision and next evaluation time. Clients display a named reason such as “Deferred by project” with a link to the source.

| Input | Rule to implement | Checks |
| --- | --- | --- |
| Status and sequencing | Store only legal direct states for the item kind. Derive remaining, available, blocked, first available and reasons independently. In a sequence, resolve the first unresolved branch before considering later branches. If it is deferred, a later sibling cannot jump ahead. In parallel, every eligible branch can proceed and the first eligible action in manual order is first available. Each eligible action in a single-actions list is first available. Apply each nested group's mode and its ancestors' eligibility. A held project makes its children unavailable. A held tag blocks tagged actions and groups, while a project carrying that tag keeps its own status. | AT-02–AT-04, AT-08 |
| Container lifecycle | A parent may contribute completed/dropped state or a flag without erasing a child's assignment. Complete-with-last-action responds to resolution of the last child in eligible project/group kinds. It is unavailable for single-actions lists. Carry cascaded completion in the originating transaction. Observe empty-group transitions and explicit child states after reopening. | AT-04, AT-05, AT-12, AT-27 |
| Direct dates, flags and tags | Restrict effective start by the latest applicable defer and effective deadline by the earliest applicable due. An explicit planned value overrides an inherited plan and affects scheduling views independently of availability. Preserve each direct value on move and identify a constraining ancestor. Verify the reference's response to conflicting direct date edits. An untagged action first added to a tagged container receives actual tag assignments. Preserve preassigned tags and do not continuously copy later parent edits. Enforce exclusivity across the tag group itself and its descendants in one transaction. | AT-05–AT-08 |
| Repeat and review | Compute a successor from a versioned series and the completed occurrence. Review uses its own project record and command. Marking reviewed records the review, calculates next review and advances the queue without completing a task. Follow the native early/late fixture before fixing the exact interval anchor. | AT-09–AT-15 |

For dates, represent a calendar day, a floating local date/time, a zoned wall-clock date/time with an IANA zone and an absolute instant explicitly. Record input precision, the chosen zone/floating policy and the applicable default time. Keep real completion/audit instants in UTC. Render ambiguous user input with its interpreted date, time and zone before commit. Test both floating travel and fixed-time travel. A shared workspace has an explicit reference zone for shared calendar-day calculations such as review scheduling, while a user's display zone and personal reminders remain personal.

Use the standard IANA timezone library and a tested calendar arithmetic library such as python-dateutil. Keep the product's rules above them. A series records regular versus from-completion schedule, unit/interval, selected days or month/ordinal pattern, anchor date, relationships among assigned dates, catch-up, end date/count and template policy for repeated subtrees. For regular repetition, a selected anchor affects scheduling when the rule restricts allowed days or dates. Otherwise advance each assigned date in its existing relationship. A regular schedule can advance one slot or skip overdue slots to the next future one. Automatically skipped slots do not consume the remaining repeat count. From-completion schedules use the selected anchor and unit-dependent rounding. Editing a historical completion timestamp leaves an already produced successor's dates intact. Test gaps, overlaps, leap dates, missing ordinals, nested series and skip-one versus stop-series before enabling those cases. Keep the observed rule or an owner-accepted difference alongside each edge fixture. ## Write and query contracts

The browser uses same-origin cookie sessions. Require CSRF protection for unsafe requests including login, secure HttpOnly session cookies in production, explicit login throttling, account recovery and session revocation. Optional OIDC must bind the correct issuer and subject. Require local MFA or verified MFA enforcement by the identity provider before internet-facing use. Operators manage accounts without a content-browsing grant in the application. The host and database operator remain trusted with server-readable content. [Django authentication](https://docs.djangoproject.com/en/5.2/topics/auth/default/) · [DRF authentication](https://www.django-rest-framework.org/api-guide/authentication/)

From a clean M2 stack, a local operator uses a one-shot management command to provision each ordinary account. Prompt for its secret without echoing it or putting it in arguments or logs. One transaction creates the account, private workspace, owner membership, Inbox and project root. Logging in brings the user directly to their own Inbox. The owner can create and rename a project, create a flat tag, capture unclassified tasks and assign the tag to them. M2's second view filters on that direct assignment. Nested tags, tag states and computed availability arrive in M3.

For local recovery before a domain or mail service exists, the operator issues a short-lived, single-use reset token and gives it to the verified account holder out of band. Store a token digest and expiry. Redemption changes the password, consumes the token and invalidates existing sessions in one transaction. A reset grants no workspace access to the operator and preserves any required MFA enrollment.

In this table, routes are relative to `/api/v1/workspaces/{workspace}`. “Member” includes viewers. “Edit” requires editor or owner. “Personal” restricts the target to the authenticated member's own records. Each write to application data carries an operation key and an explicit expectation about what exists. Named commands in the table use POST to `/commands/{name}`. For a direct record edit, `If-Match` is the strong ETag from its direct edit representation. Computed properties are served in query projections and can change with the clock. Compound commands instead include versions for the records and ordered lists touched.

| Route or command | Authority and input | Commit or response |
| --- | --- | --- |
| `POST /commands/capture` | Edit. New client UUIDs and titles with one explicit destination per item. Inbox capture may include direct tags and a proposed filing project. Direct insertion specifies a structural parent, optional anchor/list version and any direct tags. A new item asserts absence. | Preserve input order and stable IDs. A proposed project leaves an Inbox capture in its Inbox placement until filing. A direct insertion belongs to the named container immediately. M2 supports explicit moves to file items. M3 adds eligibility/automatic cleanup. An append serializes at the list end and an anchored insert checks the list revision. |
| `create-container`, `create-tag`, `set-tags`, `save-perspective` | Edit for workspace containers/tags, personal for a saved perspective. Supply new ID or current version, legal parent/kind and direct settings or validated expression. | Create folders/projects/groups or tags, manage explicit tag assignments or save a personal query. Rename a project through its item PATCH. Update the relevant list/version and return its authorized representation. |
| `GET/PATCH /items/{id}`, `bulk-edit` | Member reads direct fields. Edit sends changed fields only, with ETag or per-item versions. | Return normalized direct values and versions. Bulk edit validates all selected items and commits together. |
| `move`, `reorder`, `group`, `duplicate`, `trash`, `restore`, `cleanup` | Edit. IDs, source/destination, placement anchors, expected objects/list versions and a subtree guard if descendants are affected. | Validate under lock. Change structure, order and relevant Inbox placement atomically. Invalidate affected subtrees and views. Explicit archive/retrieve commands address archival copies. |
| `complete`, `drop`, `set-repeat`, `skip-occurrence`, `stop-series` | Edit. Item/occurrence, version and series version where relevant. | Lock and validate current occurrence/series. | `mark-reviewed`, `set-review` | Edit. Project and review version. Set-review accepts an interval or explicit next date. Mark-reviewed records the review event. | Mark-reviewed sets last-reviewed and advances the schedule. Last-reviewed is read-only in the inspector. Historical import/restore can preserve it. Return the authoritative dates and invalidate the queue. |
| `undo`, `redo` | Original actor with current write authority. Reference a reversible operation and its expected post-state. | Apply a new compensating command. Allow capture/edit/move/completion and safe batch rollback when affected post-versions still match. Refuse compensation if another edit, successor use or external delivery makes it unsafe. Redo has fresh preconditions. |
| `POST /query`, `GET /snapshot`, `GET /changes?after=…` | Member. Validated perspective or expression, scope/focus/search, pagination or signed cursor. | Apply access scope before filters/counts. Return IDs, direct/effective display values, reason, versions and invalidation metadata. Bound filter depth, predicate types and query size. Compile allowlisted operators to parameterized queries. |
| `/notes`, `/attachments` | Edit to write, member to read linked content. Supply note or target version, length, declared type and checksum for binary upload. | Sanitize notes and links, verify actual file type and size. Serve safe previews or an authorized download. Stage incomplete transfers privately, recheck quota and target version at final link, and expire abandoned uploads. |
| `/imports`, `/exports` | Owner for workspace bulk import, rollback, full export and restore. Each member can export their own personal records. Validate authority again before execution and download. | Stage and preview, commit reviewed mappings, return batch/job/manifest IDs. Version-check rollback against intervening edits. See transfer boundary below. |
| `/members`, `/invitations`, `/me/preferences`, `/me/reminders` | Workspace administration requires owner. Personal writes require current membership and target the caller. | Record permission changes atomically and notify affected sessions. Sharing an item flag, order or review does not share personal reminders, views or preferences. |

The M5 capture adapter uses a revocable, capture-only credential bound to a person and workspace. A dedicated `POST /api/v1/capture/context` checks the credential and current write authority and issues a signed context restricted to that credential and Inbox capture. The adapter can submit its capture and retry for a minimal receipt without reading a workspace snapshot, listing content or accessing a browser session's receipt. Calendar connections expose read-only events with their own IDs and freshness indicators. Personal provider tokens and delivery endpoints belong to their connecting user. Protect reusable secrets in SQL using a key supplied through deployment secrets. Nearby requests device location on demand and degrades to a place list when unavailable. Browser and provider coverage is specified in the [feature register](FEATURE_PARITY.md).

### One command, one commit

1. Authenticate, resolve the workspace and validate the signed write context. Lock the workspace's revision row and recheck membership/permission before revealing results. All workspace mutators, including membership changes, take this lock first.
2. Look up the operation key for this actor/workspace. A matching fingerprint returns the authorized prior receipt even if the original edit version is now stale. Reusing the key for a different envelope returns a conflict. A missing receipt proceeds to version, hierarchy and business-rule validation. Lock additional rows in stable ID order.
3. Apply the workspace command, record affected versions and inverse information where safe, increment the workspace revision once, and insert change records, receipt and necessary outbox work. On failure the database rolls back the whole set. After commit return affected IDs, new versions and revision. Only consuming the change feed advances the browser's cursor, so another member's intervening change cannot be skipped. [Django transactions](https://docs.djangoproject.com/en/5.2/topics/db/transactions/)

Serialize revision allocation through the locked workspace row until commit. A database sequence or timestamp assigned before commit can cause a slow transaction to land behind a cursor already delivered to another browser. Maintain sibling-list versions for order and a subtree revision that advances on descendant changes for operations such as deleting or duplicating a tree, so an unseen descendant edit cannot be lost. An individual edit checks the version of the record it changes.

| Outcome | Client behavior |
| --- | --- |
| `401` reauthentication, `403` insufficient role, `404` outside visible scope | Pause writes on session expiry. Suppress foreign IDs, counts, file metadata and conflict payloads. Revoke cached access as soon as revocation is learned. |
| `412` failed direct `If-Match`, `409` stale compound versions, incompatible anchor or key reuse | Preserve draft and base. Show authorized current state, distinguish edit/delete/move, then reload, discard or deliberately submit a new operation. |
| `428` missing required precondition, `422` invalid command | Show the field/constraint error. Do not retry unchanged input. |
| `410` expired cursor, write context or data generation | Obtain a fresh authorized snapshot. Hold pending operations for comparison. Never renew an old key into a new context. |
| Timeout or lost acknowledgement | Retain pending state and retry the identical operation with the same key. Display “Saved” only after a receipt. |

HTTP's strong `If-Match` supports conditional editing. The compound preconditions, error bodies and operation receipts are application contracts. [HTTP semantics, section 13.1.1](https://www.rfc-editor.org/rfc/rfc9110.html#section-13.1.1)

### Two-browser example for M2

Joe opens the same private Inbox in two profiles. Profile A captures “Check field notes” and loses the acknowledgement. Its retry carries the same key and item UUID. It receives the original receipt and both profiles see one item. Both now read item version 1. A renames it, producing version 2. B edits from version 1, receives a precondition failure and keeps its draft beside the current title. B can choose to reapply its edit to version 2. Moving the item to a project updates both parent lists in one commit. A third profile signed into a different account receives no item, count or event for Joe's workspace. This is a proposed AT-01/AT-17/AT-18 demonstration.

In M2 compound edits guard the complete workspace revision. A concurrent edit can therefore ask the user to compare a draft even when it affects another item. Direct item edits support a strong per-item ETag. The M2 compensating undo covers the immediately preceding ordinary completion or reopening.

## Reads, change delivery and offline editing

On opening a workspace, return its authorized snapshot and cursor from the **same** consistent database snapshot. Initial payloads contain outline metadata and direct values. Fetch large bodies separately. Start with foreground polling about every two seconds so two browsers can converge with standard HTTP and one backend process type. Back off while hidden and check immediately on resume, reconnect or login change. Deliver complete revision groups, including deletions and subtree invalidations. Reauthorize each fetch. A cursor is opaque and bound to the subject, workspace and current data generation.

Personal-only writes advance a separate per-account revision under its own lock and have a separate feed cursor. They do not publish records to the workspace feed. Commands affecting both scopes, such as revoking a membership, lock the workspace before the account and commit their authorized changes together. Each client consumes both feeds.

For standard and saved views, scope to the chosen workspace, evaluate task rules and apply the requested view or search scope. “Here” searches visible outline/sidebar content. Broader Remaining/Everything searches can reach beyond the current perspective. Observe how explicit focus composes with broad search. Use a versioned all/any/none expression tree and allowlisted fields for custom perspectives. Tag/search indexes may speed that expression while the evaluator determines the final answer. Default search covers titles, note text and tag names within the requested scope. Include the next relevant time boundary in a query result so defer, review and Forecast refresh without a new write. Refresh on a timezone or day change. [Commands](https://support.omnigroup.com/documentation/omnifocus/universal/4.10.1/en/commands/)

M6 adds account/workspace-partitioned IndexedDB records, a revisioned cache, attachment staging and an ordered edit queue. Commit the local draft, base versions and queue envelope together before showing “Pending”. Keep client-generated IDs across dependent commands. Reconcile against an authorized snapshot or feed, then replay in causal order with the original operation keys. A failed parent move blocks dependent child edits. Independent work can continue. Keep local base, draft and current server side by side for a conflict. Offer reapply/discard only where the current user still has access. A stale destructive command or ambiguous completion always needs review. A retry of a partial file upload rechecks target, checksum, job/version and quota before linking bytes. [IndexedDB](https://developer.mozilla.org/en-US/docs/Web/API/IndexedDB_API)

For a dependent queued edit, save its draft with a reference to its predecessor operation and the version field it needs. For example, a rename following an offline capture needs the capture receipt's new item version. Resolve that reference exactly once, from that receipt, before the dependent command's first send. Persist the resolved envelope before transmitting. Subsequent retries use its original key and identical preconditions. If another device edited the item after the capture, the rename will surface that conflict.

Retain detailed operation receipts, change rows and sync tombstones for **90 days from commit** by default. The server signs a write context for an actor/workspace/generation, valid for at most 90 days from issuance. An operation key combines that context's unique ID with a new UUID. A retry must present its original context. Thus no admissible retry can outlive its receipt. Trim only at expiry and never recycle a context ID. Archive and occurrence history have their own lifetimes. A missed feed window, incompatible client/queue format or generation change requires an authorized resnapshot. If the client cannot prove whether an edit survived a restored database, hold the local draft and show the difference before any new command. Rotate the server data generation after such a restore.

Only opt a trusted browser profile into persistent offline use. Persist its active account/device binding and expiry. Offline reopening is available only to that bound account while valid. Lock the cache and queue on expiry and require online authentication to switch identities. On explicit logout or account switch offer to sync, discard pending edits deliberately, or cancel the action. On completed logout purge that account's caches, queue, previews and service-worker data across tabs before showing the next account. Check permission again at replay and remove revoked workspace data as soon as the client learns of revocation. An offline device learns of a remote revocation when it reconnects. Report unavailable storage, quota errors or a failed durable write before promising a pending save.

## Files, transfers and durable work

Default quotas are **25 MiB per attachment** and **1 GiB of logical file bytes per workspace**, configurable and charged on finalization. Bound staging separately so incomplete uploads cannot exhaust storage. Store the authoritative bytes in PostgreSQL and render only approved, inert formats inline. Keep credentials, untrusted markup and third-party script out of previews. [PostgreSQL binary data](https://www.postgresql.org/docs/current/datatype-binary.html)

| Transfer | Boundary and recovery |
| --- | --- |
| Import from the reference | Accept documented TaskPaper/CSV starting formats. Parse into private SQL staging with counts, source row/path, field coverage and warnings. Bind the approved preview to the input digest, mappings and parser version. A duplicate request returns the same batch. If source IDs are absent, retain batch-local mappings and show potential duplicates on a changed export. Validate and commit into the selected workspace atomically. |
| Roll back an import | Record the post-import object, sibling-list and subtree revisions plus incoming relationships relevant to removal. Under the workspace lock validate those guards and check for later references, including new children, tag assignments and attachment links from outside the batch. Undo batch-owned changes together only if the reversal preserves intervening work. On conflict leave the complete batch intact and identify the affected records to the owner. |
| Human-readable CSV export | A workspace owner can export an ordered UTF-8 CSV of selected authorized items. Include item and parent IDs, kind, sibling position, title, direct status, tag names, dates with timezone intent and plain note text. Apply spreadsheet-safe text handling to each user-controlled cell and serialize fields with a CSV writer. Explain the display escaping, supported spreadsheet import modes, selection, row count and omissions (formatting, file bytes, recurrence, views, trash and memberships). The complete application bundle preserves original text for restoration. [Spreadsheet export considerations](https://community.owasp.org/attacks/CSV_Injection) |
| Portable application export | Make a versioned manifest with record kinds, schema versions, stable IDs/references, workspace and snapshot revision, counts, byte lengths and checksums. Include hierarchy, order, direct dates/status, tags, notes/files, repeat/occurrence history, reviews, archives and recoverable trash with original placement. Include committed import batch identities, source fingerprints, mappings and any existing rollback eligibility/conflicts. A workspace owner exports shared content. The personal section contains only the caller's views, preferences, reminders and exportable adapter settings. Membership descriptors are informational. |
| Restore and rebind | Validate the package before writing a clean workspace. Preserve or consistently remap IDs, including references in trash, batch rollback metadata and source mappings. Test the same source import again for duplicate prevention. Re-evaluate rules and compare counts, ordering and file hashes. Carry displayable history across, open a fresh undo stack and issue fresh receipts, stream cursors and write contexts for new destination commands. Source operations cannot be replayed. Owners reissue memberships and reconnect reminder targets and credentials before delivery resumes. Pending transfer staging, passwords, sessions, push endpoints, leases and deployment keys stay outside the portable format. Operational disaster recovery covers identities, memberships, keys and durable job state under [operations](OPERATIONS.md). |

Insert jobs in the same commit as the state that schedules them. Claim a bounded batch of due rows with a short SQL transaction and a lease token. Perform slow work after releasing locks. Record success, failure or timeout only if the lease still matches. Expired leases can be reclaimed and retries use bounded backoff. Recheck current membership and whether the task/reminder version still warrants delivery immediately before external work. Key deliveries by logical event/recipient/channel and provide provider idempotency keys where supported. A crash after provider acceptance but before local confirmation can otherwise leave a delivery ambiguous. Record that state for reconciliation and expose exhausted jobs for deliberate retry. Recurring-task successors stay in the completion transaction. [PostgreSQL locking for queue consumers](https://www.postgresql.org/docs/current/sql-select.html#SQL-FOR-UPDATE-SHARE)

## Interaction contract

Keep one command dispatch path for keyboard, pointer, contextual menus, command palette and inspector. Track selection by stable IDs, and expansion, scroll anchor and last focus by user/device/perspective. In a bulk edit show mixed values and change only the named fields. Keep text-entry and outline-navigation keymaps distinct. Provide keyboard equivalents for drag, indent, outdent, moving between projects, pane resizing and inspection. Do not consume browser-reserved bindings. Narrow layouts expose the same outline through drawers or focused screens. Honor reduced motion, visible focus, density, text size and light/dark preferences.

M1 uses synthetic captures with editable properties, move between projects, rediscovery in a second view, completion and undo. M2 swaps in authenticated persistence and pending/saved/conflict feedback. A virtualized outline must preserve the active row, keyboard selection and accessible tree position while rows enter and leave the viewport. The measurement conditions and targets for 10,000 tasks live in [verification](VERIFICATION_PLAN.md). The [roadmap](PROJECT_PLAN.md) sets the gates for the prototype and first persistent slice.
